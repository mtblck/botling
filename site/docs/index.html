Introduction

Seedkin turns any string, such as a user id, into a small pixel avatar, as an SVG string. The same seed always draws the same avatar, so there's nothing to store but the id you already have.

Every style has its own entry point, so an app only ships the styles it uses. Botling, the robots, is the first: seedkin/botling. Snoot (animals), Noggin (people) and Beastie (monsters) are in Preview.

Coming from the botling package? Import from 'seedkin/botling' instead of 'botling': every seed draws the same robot as botling 1.2.0.

Install

npm install seedkin
pnpm add seedkin
yarn add seedkin
bun add seedkin

Seedkin has no runtime dependencies and ships as ESM with TypeScript types. It runs in browsers, Node 22 and up, and edge runtimes. No build step? See Plain HTML.

Use

import { botling, botlingDataUri } from 'seedkin/botling';

// An SVG string, for inlining.
const svg = botling(user.id);

// A data: URI, for <img src> or CSS url().
const src = botlingDataUri(user.id, { size: 48 });

Every style has the same pair: snoot() and snootDataUri(), noggin() and nogginDataUri(), beastie() and beastieDataUri(). Each style salts the seed, so one id's robot, animal, person and monster are unrelated.

Choosing a seed

Use an opaque, stable id as the seed (a database id or UUID), not an email address or username. The seed never appears in the SVG, but anyone can render the robot for a guessed email and compare.

The seed is used as given, apart from Unicode normalisation (NFC), so José draws the same robot however the é was typed. It isn't trimmed or lowercased: Ada and ada are different robots, so tidy the seed first if your ids vary like that.

For someone without an id, randomSeed() gives a readable one, like plucky-servo-427. Store it: that's what brings the same avatar back. See Random robots.
